## Файл должен быть кому-то нужен

Очистка (`FILE_CLEANUP_ENABLED`) удаляет загруженный файл, на который дольше
суток не ссылается ни одно событие. Поэтому обложку площадки мало загрузить —
её надо сразу поставить хотя бы одному событию, иначе id в конфиге через день
будет вести в пустоту.

Четыре обложки выше закреплены: каждая стоит минимум у одного события (в том
числе у прошедших — им картинки проставлены 2026-09-30 ровно ради этого).

У `kp_pyl.jpg` событий на проде ещё нет, закрепить её не за что. Поэтому в
`channels.json` её id **не прописан**: при первом импорте из @kp_pyl загрузить
файл заново (`POST /api/v1/uploads`), поставить событию и только тогда вписать
id в `default_venue.cover_file_id`.

Одна картинка на много событий — это безопасно: очистка файлов удаляет только
файлы, на которые не ссылается ни одно событие
(`backend/internal/files/repository.go`), а замена обложки у события старый
файл не удаляет.

Фото из постов каналов сюда не берём: в условиях разрешения записано
«фотографии не копируем». Новую обложку — `render.py`, см. docstring.

## Событий без обложки в афише быть не должно

Правило с 2026-10-01: каждое событие выходит с логотипом площадки или
организатора. Сборщики подставляют обложку сами — площадки
(`default_venue.cover_file_id` / `venue.cover_file_id`), а если её нет, то
канала (`channels.json` → `cover_file_id`, так сделано для Ad Marginem).
Если нет ни той, ни другой, в отчёте стоит «НЕТ ОБЛОЖКИ — без логотипа не
публиковать»: сначала сделать и загрузить обложку, потом заводить событие.

Обложки `admarginem.jpg` и `ges2.jpg` закреплены событиями 01.10.

Загрузка без ручной формы: в открытую вкладку админки добавить
`<input type=file>`, положить в него файл инструментом загрузки браузера и
отправить `FormData` на `POST /api/v1/uploads` с токеном из `localStorage`.
