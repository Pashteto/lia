# Кликабельные плитки дашбордов

**Дата:** 2026-08-12 · **Статус:** одобрено пользователем

## Проблема

Ни одна стат-плитка в продукте не кликабельна — навигируют только баннеры,
CTA и чипы. Организатор видит «Черновики 01» в кабинете и не понимает, как
открыть черновик (фильтр в «Мои события» — только локальный стейт, URL нет).
Системно: непонятно, какие зоны — кнопки, а какие — просто цифры.

## Решение — язык аффордансов

**Стрелка в капшене (`ЧЕРНОВИКИ →`) = плитка кликабельна.** Плюс
`cursor-pointer` и существующий `hover-invert` (паттерн `EventModule` /
баннера заявок). Плитка без стрелки — заведомо не кнопка. Никаких плиток,
ведущих «в никуда».

## 1. Примитив: `Cell` c опциональным `href`

`components/ui/Cell.tsx`: prop `href?: string`. С `href` рендерится
`next/link` c `swiss-focus hover-invert cursor-pointer`, капшен получает
суффикс ` →`. Без `href` — текущий инертный `div` без стрелки. Для
`invert`-плитки hover — обратная инверсия (в бумагу: `hover:bg-paper
hover:text-ink`). `CellStrip` не меняется.

## 2. Энейблер: URL-фильтр в «Мои события»

`MyEventsBrowse` (`/events/mine`):
- читает `?status=all|published|pending_review|draft|cancelled` как начальное
  значение фильтра (невалидное значение → `all`); прецедент —
  `AdminOrganizers` + `?filter=`;
- клик по чипу пишет статус в URL через `router.replace` (прецедент —
  `/me?tab=`), `all` очищает параметр.

## 3. Кабинет организатора `/organizer` (`OrganizerHub`)

| Плитка | Цель |
|---|---|
| Опубликовано | `/events/mine?status=published` |
| На модерации (invert) | `/events/mine?status=pending_review` |
| Черновики | `/events/mine?status=draft` |
| Всего записей | инертна, без стрелки (нет осмысленной цели) |

Мобильная тройка Опубл./Модер./Черн. — те же цели.

## 4. Админ-обзор `/admin` (`AdminOverview`)

| Элемент | Цель |
|---|---|
| Ждут модерации | `/admin/moderation/events` |
| Организаторов | `/admin/organizers` |
| Пользователей | `/admin/users` |
| Событий всего | инертна (реестра всех событий нет) |
| Моб. «Модерация» | `/admin/moderation/events` |
| Моб. «Верификация» | `/admin/organizers?filter=pending` |
| Строки превью «Очередь модерации» | `/admin/moderation/events` |
| Строки «Заявки на верификацию» | `/admin/organizers/{id}` |

Строки превью — ссылки целиком (те же hover-инверсия и focus, стрелку в
строках не добавляем — это списочные строки, не KPI-плитки; их кликабельность
передаёт hover + курсор, как у существующих строк-ссылок админки).

## 5. Профиль `/me` (`MeProfile`)

«Посещено» → `/me?tab=past`, «Подписки» → `/me?tab=follows`, «Заявки» (моб.)
→ `/me?tab=applications`. Все цели уже существуют.

## 6. Тесты

- `Cell`: с `href` — рендер ссылки, стрелка в капшене; без — div и без
  стрелки.
- `MyEventsBrowse`: `?status=draft` → активен фильтр черновиков; мусорное
  значение → `all`.
- Визуальная проверка на локальном стенде: кабинет, админ-обзор, /me.

## Вне рамок (YAGNI)

Deep-link выбранного события в админ-очереди (селект — локальный стейт);
реестр «всех событий»; запись фильтра админ-модерации в URL; переработка
«ленты активности» кабинета (заглушка остаётся).
