# Внешняя регистрация: whitelist платформ, платные события, скрытая вместимость

**Дата:** 2026-08-12 · **Статус:** РЕАЛИЗОВАНО И ЗАДЕПЛОЕНО LIVE 2026-08-12 (образы extreg-r1, prod schema 26) — см. runbook `docs/superpowers/runbooks/2026-08-12-external-registration-deploy.md`

## Контекст

Платформа не принимает оплату. Режим `signup_mode = external` уже существует
end-to-end (миграция 000012, поле `events.external_registration_url`, кнопка
«Записаться на сайте организатора» в `SignupCTA.tsx`), но ссылка валидируется
только как `https?://` — любой домен проходит. Нужны: whitelist доверенных
платформ Рунета, честный UX для платных событий без ссылки, и «ограниченная
вместимость без числа», когда остатками управляет внешняя платформа (TimePad
и т.п.).

Принятые продуктовые решения:

1. **Платное событие без внешней ссылки** — разрешено; рядом с ценой подпись
   «Оплата на месте». Ссылку не требуем.
2. **Whitelist + модерация**: известный домен публикуется сразу; неизвестный
   не блокируется, а отправляет событие в `pending_review` (первое реальное
   использование статуса). Админ одобряет разово или добавляет домен.
3. **Скрытая вместимость** — флажок «количество мест ограничено» без числа;
   число нигде не хранится, остатки смотрят на сайте регистрации.
4. **Текст кнопки** — имя платформы из whitelist («Билеты на TimePad»);
   неузнанный домен → текущий текст + домен подписью.
5. **Хранение** — таблица в БД + seed; минимальный admin-CRUD.
6. **Архитектура** — синхронная проверка по таблице при create/patch; без
   активных HTTP-проверок ссылки.

## 1. Данные (миграция 000026)

Таблица `trusted_platforms`:

| колонка | тип | примечание |
|---|---|---|
| `id` | uuid PK | |
| `domain_suffix` | text UNIQUE NOT NULL | punycode, без схемы: `timepad.ru` |
| `display_name` | text NOT NULL | «TimePad» |
| `category` | text NOT NULL | `ticketing \| afisha \| gov \| social` |
| `is_active` | boolean NOT NULL DEFAULT true | мягкое отключение |
| `created_at` | timestamptz NOT NULL | |

Матчинг: хост URL равен `domain_suffix` **или** оканчивается на
`.domain_suffix` (покрывает `msk.kassir.ru`, `org.timepad.ru`). Сравнение —
после нормализации хоста в punycode; суффиксы в seed уже в punycode
(`xn--80atdujec4e.xn--p1ai` для культура.рф), иначе матчер обходится
юникод-двойниками. Анти-обход: `timepad.ru.evil.com` не матчится (суффикс
проверяется по границе точки с конца).

`events` — два поля:

- `capacity_limited boolean NOT NULL DEFAULT false` — «мест ограничено, число
  не показываем»; осмысленно только при `signup_mode='external'`.
- `external_url_verified boolean NOT NULL DEFAULT false` — снимок результата
  проверки на момент сохранения; позднейшие правки whitelist не меняют статус
  уже опубликованных событий задним числом.

Seed (~21 запись из исследования 2026-08-12): `timepad.ru`,
`afisha.yandex.ru`, `kassir.ru`, `qtickets.ru`, `qtickets.events`,
`ticketscloud.com`, `ticketscloud.org`, `intickets.ru`, `radario.ru`,
`ticketland.ru`, `ponominalu.ru`, `live.mts.ru`, `afisha.ru`, `kinopoisk.ru`,
`vk.com`, `events.nethouse.ru`, `leader-id.ru`, `culture.ru` (+punycode
`культура.рф`), `mos.ru`, `vmuzey.com`, `kudago.com`. Отклонены: Eventbrite
(ушёл из РФ), `taplink.cc`/`t.me` (непроверяемый редирект), `bigbillet.ru`.
Ограничение: собственные сайты музеев/театров (bolshoi.ru и т.п.) в whitelist
не вносим — они идут через модерацию.

## 2. Бэкенд: валидация и модерация

В `events.Service` (create/patch), когда `signup_mode='external'`:

1. Парсинг URL: строго `https://`, без userinfo, хост не IP-адрес. Нарушение —
   единственная жёсткая 422 (как сейчас пустой URL).
2. Хост → punycode → суффикс-матч по активным `trusted_platforms`.
3. Матч есть → `external_url_verified = true`, публикация как обычно.
4. Матча нет → `external_url_verified = false`; при попытке публикации событие
   получает статус `pending_review` вместо `published`. Черновики не
   трогаем — проверка только на пути к публикации. В админ-модерации админ
   либо публикует событие разово, либо добавляет домен в whitelist (что
   разблокирует и будущие события).

«Оплата на месте» — чисто отображение (`price > 0 && signup_mode != external`),
без изменений в БД и бэкенде.

## 3. API

- `GET /events/{id}` и списки: + `externalPlatformName` (display_name из
  whitelist или null, вычисляется при чтении), + `capacityLimited`.
- `POST/PATCH /events`: принимают `capacity_limited`; в ответе
  `moderationRequired: true`, если событие ушло в `pending_review` — фронт
  объясняет организатору, что происходит.
- `GET /api/v1/trusted-platforms` — публичный read-only список (для живой
  подсказки в форме).
- `GET/POST/DELETE /admin/trusted-platforms` — минимальный CRUD (admin-гард
  как у существующей модерации).

## 4. Фронт организатора (`CreateEventForm.tsx`)

- Режим «Внешняя ссылка»: под полем URL живая подсказка — домен узнан →
  «Платформа: TimePad» (зелёная); не узнан → «Неизвестная платформа — событие
  уйдёт на проверку модератору» (жёлтая). Список доменов — один запрос
  `GET /api/v1/trusted-platforms`.
- Чекбокс «Количество мест ограничено» вместо скрытого поля вместимости
  (показывается только в режиме external).
- Платное + обычная запись: подпись-предупреждение «Посетители увидят
  „Оплата на месте“» — нового состояния не храним.

## 5. Фронт посетителя (`SignupCTA.tsx`, `EventDetailView.tsx`)

- Кнопка external: `externalPlatformName` есть → «Билеты на {name}» (платное)
  / «Записаться через {name}» (бесплатное); подпись — домен ссылки. Нет →
  «Записаться на сайте организатора», подпись «Переход на {домен}».
- Блок «Места» при `capacityLimited` → «Ограничено · наличие на сайте
  регистрации».
- Платное + обычная запись → под ценой «Оплата на месте».
- Попутный фикс вёрстки: CTA-колонка пересекает `border-l` — расширить
  `grid-cols-[1fr_200px]` до `[1fr_248px]` в обоих местах
  `EventDetailView.tsx` (баг от 2026-08-12, «Вы записаны» + календарные
  ссылки шире 200px).

## 6. Ошибки и тесты

Ошибки: только некорректный/не-https URL даёт 422; неизвестный домен никогда
не теряет данные — путь модерации.

Тесты:

- Go-юниты матчера: точный домен, поддомен, punycode (`культура.рф`),
  анти-обход `timepad.ru.evil.com`, IP-хост, `http://` → отказ.
- Сервисные: create/patch external с неизвестным доменом → `pending_review` +
  `moderationRequired`; с известным → `published` + `external_url_verified`.
- Фронт: zod-схема (чекбокс вместо capacity при external), рендер CTA по
  веткам узнан/не узнан/платно/`capacityLimited`.

## Вне рамок (YAGNI)

Приём оплаты на платформе; активная HTTP-проверка ссылок; синхронизация
остатков с TimePad по API; хранение скрытого числа мест; отдельный статус
модерации для ссылок (используем общий `pending_review`).
