## What shipped

Five QA defects plus two feature requests:

1. **Event creators were not organizers.** An `organizers` row was written only
   by the profile form, so someone who went straight to «создать событие» was
   «Зритель» in the admin registry, absent from the verification board and
   unfollowable. Creating an event now mints an auto-verified profile
   (`organizers.EnsureForOwner`), and migration 023 backfilled the rest.
2. **Verify-email banner survived until a re-login.** Backend was innocent —
   proven on prod: the same bearer token returns `email_verified: true`
   immediately after `POST /auth/verify-email`. The client read the flag once
   per session; an unverified tab now re-reads `/auth/me` on refocus.
3. **Applications checkbox unclickable and struck through.** A fixed 44×44
   button inside a 26px grid track: the column rule cut the box and the next
   cell swallowed the right half of the hit area.
4. **Cover upload died as «Failed to fetch».** See the nginx section below.
5. **No way to remove an event.** Organizers can now cancel; cancelled events
   leave the feed but stay readable for registered attendees.
6. **`/admin/organizers/{id}`** — the organizer's events, any status, with
   takedown/reinstate.
7. **Daily event cap** — 3/day (`EVENTS_DAILY_LIMIT`), per-organizer override
   in `organizers.daily_event_limit`, editable on the new admin page.

## The trap that cost a rollback: purego makes the binary dynamic

The HEIC decoder (`github.com/gen2brain/heic`) ships two backends: a pure-Go
WASM one and a libheif one reached through `github.com/ebitengine/purego`.
purego emits `//go:cgo_import_dynamic` directives, and **those put the Go
linker in dynamic mode even under `CGO_ENABLED=0`**. The runtime image is
`FROM scratch`, which has no `/lib64/ld-linux-x86-64.so.2`, so every start
logged:

```
exec /lia: no such file or directory
```

`docker compose up` reported the container as *Started* — the crash loop was
only visible in `docker logs`. Prod was down for ~4 minutes until the rollback.

**Fix:** build with `-tags nodynamic` (now in `backend/Makefile`). That drops
the purego path and keeps the WASM decoder, which still decodes real HEIC
(verified against the decoder's own `test.heic`: 150 KB → 1346×1346 JPEG).

**Check this before every backend deploy from now on:**

```bash
docker create --platform linux/amd64 --name x lia-backend:<tag> && docker cp x:/lia ./lia && docker rm x
file ./lia    # must say "statically linked"
```

A dynamically linked binary must never reach the box.

## nginx was the real cause of «Failed to fetch»

There was no `client_max_body_size` anywhere in the nginx config, so the 1 MB
default applied. Its 413 is generated by nginx and therefore carries **no
CORS headers**, so the browser turned an ordinary HTTP status into a network
error and the app printed `Failed to fetch`. Anything between 1 MB and the
app's own cap — i.e. every phone photo — died there.

```bash
ssh vdska2
sed -i 's|^    server_name api.presence.tarski.ru;|    server_name api.presence.tarski.ru;\n    client_max_body_size 12m;|' /etc/nginx/sites-available/presence
nginx -t && systemctl reload nginx
```

Backup of the previous file: `/opt/lia/nginx-presence.bak-20260809`.
Keep this above the app's `maxBytes` (10 MB) or the symptom returns.

## Procedure (as executed)

1. `pg_dump` both DBs → `/opt/lia/backup-pre-qa09aug-{lia,gateguard}-20260809-194131.sql.gz`.
   **The Lia database is `lia_prod`, not `lia`.**
2. nginx `client_max_body_size 12m` + reload; verified with a 3 MB unauthenticated
   POST going 413 → 401.
3. Build from an isolated worktree (`git worktree add --detach`), copying the
   three gitignored generated trees in first — unchanged from the qa31 runbook.
   `api/swagger.yaml` was untouched on this branch (`diff -q`), so copying the
   generated server/models was safe.
4. **Frontend build args:** `NEXT_PUBLIC_API_URL` and `NEXT_PUBLIC_YANDEX_MAPS_KEY`.
   The maps key is **not in any file on the box** — it lives only as an env var
   on the running container:
   `docker inspect lia-frontend-presence --format '{{range .Config.Env}}{{println .}}{{end}}' | grep -i yandex`
   The first build passed an empty key; caught by grepping the bundle for the
   key before shipping. Do that check every time:
   `docker run --rm --entrypoint sh <image> -c "grep -rl '<key>' /app/.next | head -2"`
5. `docker save | gzip | rsync` → `docker load`. **Use `rsync --partial`, not
   `scp`** — the box reset the connection at 47% of the 215 MB frontend tarball
   and rsync resumed instead of restarting.
6. Rollback tags `*:rollback-qa09aug-20260809`, then backend cutover, then the
   frontend container swap (stop → rename → `docker run`).
7. Migrations 023 + 024 applied automatically via `backend-migrate-1`
   (`23/u backfill_organizer_profiles`, `24/u organizer_daily_event_limit`);
   `schema_migrations` = 24, not dirty.
8. Verification (below), then prune.
